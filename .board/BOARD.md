### 实验二：`scripts/exp_ru_recoverable2.mjs`（加位置约束的关键判别）

> ⚠️ **我第一版实验 `scripts/exp_ru_recoverable.mjs` 的结论是错的，勿引用它的 86.7%。**
> 原因：它允许词素出现在**任意位置**，于是产出 `Лена←на(prefix)@2`、`Эдем←де@1`、`арест←ре@1`、`Краков←ко@3` 这类**无意义假命中**，把上限虚抬到 86.7%。这是"判别集设计错误"的现场教学，对应 `AGENTS.md` §4.1 的教训。**正确做法是加位置约束**：prefix 只允许词首、suffix 只允许词尾、剥离后剩余 ≥3 字符。

| 构成 | 数量 | 占比 |
| --- | --- | --- |
| **可剥离合法前缀或后缀（真·可提升空间）** | **310** | **39.2%** |
| ├ 仅前缀 | 53 | 6.7% |
| ├ 仅后缀 | **227** | **28.7%** |

### 结论与警告

- **45% 可达**：只需 356 / 791 命中，当前 244，缺口 **112 词**；可提升空间 **310 词**，余量充足。
- **但 310 词的构成决定了路径风险**：主力是「**仅后缀 227 词**」，即必须靠**词尾剥离**。
  **而这正是历史上重创过本项目的同一个动作**——`AGENTS.md` §4.1 记录：`hasRootBefore` 规则使**俄语拆解率 61.6% → 17.1%**（被迫回退）。

### 真正的机制（三关，缺一不可）

一个俄语词要被 `breakdownWord` 拆出，必须**同时**通过：

1. **首片段规则**（`index.ts:851-855`）——**这是关键的一关**
   ```ts
   if (parts.length && parts[0].start >= 2) {
     const gap = mw.slice(0, parts[0].start);
     const explained = all.some((x) => x.m.kind === 'prefix' && x.stem === gap);
     if (!explained) return [];
   }
   ```
   ⇒ **词首必须有已知词素**（一个 root 或 prefix 精确覆盖词首）。否则 DP 只能从位置 ≥2 起，整体作废。
   **词尾知道再多后缀也救不了词首缺根。**
2. **单字符前缀支撑规则**（`index.ts:773-781`）——俄语单字符前缀（`в-`/`с-`/`у-`/`о-`）必须紧邻一个 ≥3 字符的已知词根/后缀（`rest.startsWith(x.stem)`）。
3. **覆盖率阈值**（`index.ts:842`）——已知词素覆盖字符数 / 词长 **≥ 0.55**。

  要补 112 个词根才能达标，且每个都需人工审定。**不推荐作为主路线。**

- **路线丙（推荐）：不需要二选一，而是"先做零风险增量，再用判别集决定是否动阈值"**

  3. **阈值杠杆的敏感度已量化**：0.55→0.50 即达 **46.0%**（`scripts/exp_ru_threshold.mjs`），但这是一次性、全局、不可回退的放宽，**必须最后才考虑**，且必须证明它没有复活已知误拆。
