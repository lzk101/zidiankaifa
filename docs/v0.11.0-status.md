## 3. 构建链（顺序不可换，三条命令）

```powershell
$base = 'D:\lzk17\Documents\zidiankaifa\.android-toolchain'
$env:JAVA_HOME        = "$base\jdk\jdk-21.0.12.1+1"   # ★ 必须 JDK 21（Capacitor 8 写死 VERSION_21）
$env:ANDROID_HOME     = "$base\sdk"
$env:ANDROID_SDK_ROOT = "$base\sdk"
$env:GRADLE_USER_HOME = "$base\gradle"

# ① 核心与前端产物（core 改了必须先 build，否则测/打的是旧实现）
pnpm --filter @zidiankaifa/core build
pnpm --filter @zidiankaifa/web  build

# ② 把 web 产物同步进 Android 工程（★ 干净 clone 后不跑这步，打出的 APK 是空壳）
pnpm --filter @zidiankaifa/mobile sync

# ③ 签名 release APK（缺凭证会**显式失败**，不产 unsigned 包）
cd apps\mobile\android
.\gradlew.bat assembleRelease
```

**产物**：`apps/mobile/android/app/build/outputs/apk/release/app-release.apk`

⚠ **未跑 ① ② 就 ③ 会得到「用旧 web 资源签名的包」** —— 包是好的、签名是对的、**内容是旧的**，
这种包**能装上、能跑、看不出错**，是最难发现的一类假绿。⇒ G4 就是专门拦它的。

## 4. 发布前逐条核验命令（照抄可跑）

```powershell
$base = 'D:\lzk17\Documents\zidiankaifa\.android-toolchain'
$apk  = 'apps\mobile\android\app\build\outputs\apk\release\app-release.apk'

# G3 签名指纹（规范化后比较！三种打印格式不可直接比字符串）
$env:JAVA_HOME = "$base\jdk\jdk-21.0.12.1+1"
& "$base\sdk\build-tools\35.0.0\apksigner.bat" verify --print-certs $apk

# G4 包内 web 资源 hash 是否等于当前 apps/web/dist
#    包内路径：assets/public/assets/index-<hash>.js
#    比对：apps/web/dist/assets/ 下的实际文件名

# 产物完整性（写进 Release Notes）
(Get-FileHash $apk -Algorithm SHA256).Hash
(Get-Item $apk).Length
```

**G3 通过判据**：`apksigner` 输出的 SHA-256（**无冒号小写**，64 位）=
`d37c04a813037cb62b45a7e0f8ac4c7689b86e3ee0a19eba0e356a0a3a30851e`
（规范化规则见 `apps/mobile/KEYSTORE.md`）

## 5. 发布动作（G1–G6 全绿后才执行）

1. bump 版本：4 个 `package.json` ＋ 3 处文本（`apps/web/src/App.tsx` · `SettingsPanel.tsx` · `apps/sync-server/src/index.ts`）⇒ `0.11.0`

6. `git add <明确路径>` → commit → push → `git tag v0.11.0` → push tag
