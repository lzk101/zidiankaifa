### 3.3 v0.10.0（本轮）—— 生词本语言分离 ＋ 词根分类独立面板

**性质**：**设计正确性缺陷**（**不是**「正在丢数据」）。`book`（生词本）表主键**只有 `word`** ⇒ ① 同拼写英/俄词**无法共存**（第二条**静默写不进去**）；② `localStorage` 路径同样按 `word` 去重（**静默丢弃**）；③ `bookRemove` 未传语言 ⇒ 删一个语言**连带删掉另一语言**；④ 删俄语词时墓碑 `lang` 被 `?? 'en'` 写成 `'en'`。**实测英俄同形词 = 0 条** ⇒ 本机现有数据**未实际丢失**，一旦手动收藏同形词即触发。

- **修法**：`book` 主键 → **`PRIMARY KEY (word, lang)`**（新库直建；老库**自动迁移**：建新表 → `INSERT SELECT` → 换名，全程 `BEGIN IMMEDIATE` 事务 ＋ 行数守卫 `if (after < before) throw`）；SQLite 与 `localStorage` 两条路径、全部 UI/IPC 调用点**显式传 `lang`**；`bookRemove` / `bookUpdate` **不再隐式回退 `'en'`**（改由 `existingLangForWord(db, word)` 决定墓碑语言）；`localStorage` 旧**裸数组**在首次读取时按 `isCyrillic(word)` 归语言并写回一次（**幂等、旧数据不丢弃**）。
- **UI**：生词本内 🇬🇧/🇷🇺 子页签（**仍只有一个「📚 生词本」入口**）＋ 各自独立的「共 N 词」与状态计数 ＋ 添加框**自动判语言 ＋ 手动覆盖**；**新增顶层第 5 面板「🌱 词根分类」**（只归类**生词本内**的词，空态显示引导文案、**不回退**成全库词根表 —— 与 `/lexicon` 的职责区分已写进代码注释）。

### 3.5 v0.8.0 修复 —— 词首单字符间隙的假词根误拆（D1）

**用户可见症状**：`плескание`（溅水）的词族卡显示 **`лес-`（森林）** 的 40 个词；同类 `хлестаться`→`лес-`、`анестезия`→`нес-`、`ателье`→`тел-`；全库 101,512 条中 **342 词**呈此形态（**267 误拆 + 75 真前缀**）。

- **根因**：`packages/core/src/db/index.ts` 两道「词首间隙」守卫**恰好都放过 `gap === 1`**（守卫一 `if (parts.length === 1 && parts[0].start === 1) return [];` 要求单片段；守卫二 `if (parts.length && parts[0].start >= 2)` 要求 ≥2）。**覆盖率阈值完全无效**（`плескание` 8/9 = 0.89 ≫ `BREAKDOWN_MIN_COVERAGE = 0.55`）。
- **修复**：一行 `>= 2` → **`>= 1`**。不选「无条件禁止 gap=1」是因为会误杀 `удачный`（`у- + да- + -ный`）。
- **效果**：假前缀组 **267 → 0**（四项独立检验确认，非部分修复）；真前缀组 **75 → 75（0 误杀）**；尺子 R 30.85% → **30.09%**（−0.76pp，退的 6 词全是被消除的假拆解）；尺子 A 33,441 → 33,174（−267）；测试 226 → **480**。

## 7. 已知约束与"非缺陷"清单（避免误判）

1. **截图里卡片空白 ≠ 数据为空**：`ZIDIANKAFA_SHOT` 的 `capturePage` **只截视口**。v0.7.1 排查中曾据此误判「词根词缀拆解」为空，实际拆解卡在词源卡**下方视口外**。用 `browser_snapshot` 或 `ZIDIANKAFA_DUMP` 验证。
2. **俄语模式查英语词显示「未收录」是设计**（v0.2「英俄分离」需求），不是 bug。
3. **中文反查英俄交错**是 auto 模式的刻意设计；用语言切换器可强制隔离。
4. **`COLLATE NOCASE` 对西里尔无效**，俄语专名查询必须走 `caseVariants()`。
5. **不要在 `SCHEMA_SQL` 里给新列写 `CREATE INDEX`**（老库会崩 `no such column`）。
6. **改算法前先建正反例判别集**——本项目在 `breakdownWord` 上连续 4 次调参回退的教训见 `AGENTS.md` 第 4.1 节。
7. **引用任何覆盖率/质量数字必须带尺子口径**（R / A / B 不可互比；空洞有「总数」与「最大单段」两口径）。这是本项目多轮互指错误的根源，已写入 `AGENTS.md` 铁律 7。
8. **测试文件的词库路径必须与 cwd 无关**：`pnpm --filter <pkg> test` 的 cwd 是**包目录**，写成相对路径会崩 `unable to open database file`（`errcode: 14`），而从仓库根直接 `node` 跑却正常 ⇒ **假绿**。新增测试必须两种 cwd 各跑一次（`AGENTS.md` 铁律 6）。
9. **尺子 R 是可被伪造的 KPI**（v0.8.0 裁决十三）：机械补 2 字符片段可达 45.76%，但 **91.9% 的增益来自 2 字符片段**，会造出 `безаварийный → без- + ва- + -ный`（空洞 4）这类空心骨架 ⇒ **R 不得单独使用**，必须与质量守卫（空洞口径A/B）同看。
10. **`loses`（可拆→不可拆的集合差分）不等于回归**：`антияпонский` 从碎片式变完整拆解也会被记成 "lost" ⇒ 判真实回归**必须逐词比对 `parts`**。同时**计量值不因定性为改善而改写**（v0.9.0 的 `loses` 是 **2**，即使那 2 个词是净改善）。
11. **「63 词真前缀组」是混合计数** = 真族 10 + 假族 26 + 27 词不可判定（库内无 `chain[].parts`）⇒ **不得读作「63 词全部正确」**；它作为**守卫地板**有效，**不作为正确性证据**。
12. **`да-` 假族的表述口径（逐字，禁用「边缘可辩护」与「≥N」）**：「**范围决策 · 已知延期缺陷（T20 逐词核证假族 26 词；`da-` 首片段组共 63 词，另 27 词因库内无 `chain[].parts` 无法判定）**」。
13. **UI 内嵌版本号**：`apps/web/dist` 是构建产物。v0.8.0 曾因文件策略未重建而显示 v0.7.1（**已闭环**）；今后若 build 被阻塞，Release Notes 必须披露版本号滞后。
14. **备份快照的 sidecar 不是「第二份备份」**：`VACUUM INTO` 产出的 `.bak-<ISO>` 在被校验打开后会生成 `-wal` / `-shm` sidecar ⇒ **计数类断言必须精确匹配文件名全形**（用 `startsWith` 会把 sidecar 算成备份）。测试侧已以 `REUSE_LOG_RE` ＋ 3 条钉死断言固化。
15. **跨启动备份累积是「有意取舍」，不是缺陷**：迁移**每次启动都失败**时每次会新增一份 ~494 MB 快照（实测 `[1,2,3]`），**不做自动清理**（备份是数据安全的最后一道防线，宁可占磁盘也不删）⇒ 排查后**人工删 `.bak-*`**。同时注意：**T48 之后「备份失败」不再静默降级** —— 后置校验已在 `openDatabase()` 出口，`book` 未迁到复合主键即**响亮抛错**（桌面端表现为弹窗 ＋ `app.exit(1)`）。
