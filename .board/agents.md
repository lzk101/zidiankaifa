## 0. ⚠ 三条必读（否则会误用本册）
1. **本工具层没有「删除 agent」的 API。** 可用通道只有三条：`list_agents`（只读）· `interrupt_agent`（停**当前一轮**）· `send_message`（**= 发起新一轮 = 唤醒**）。⇒ **「清理临时 agent」的实际含义 = 台账化 ＋ 标记可回收 ＋ 报主管不复用，不是物理删除**。本册**禁止**把「已标记」写成「**已删除**」或「已回收」。
2. **`ready` ≠ 会话结束、上下文已释放**（它只表示「可被 `send_message` 续跑」）⇒ 把它当「已死」随手重派 = **重复消耗上下文 ＋ 高概率产出与既有结论冲突的第二版**（本册要防的主要浪费）。且 `ready` 是**唯一状态值**，**不区分**「已完成并落盘」「失败被放弃」「从未真正开始」⇒ **不得由 `ready` 推出任何完成度结论；完成度只能由落盘证据判定，无证据即未落盘**。
3. **label 是 agent 创建时的任务描述，不等于当前职责**（三个业务常驻的 label 已过时，见 §2）。**常驻 agent 的 label 为创建时历史、只读，职责以本册 §1/§2 为准**（裁决 A，坐标 `TASKS.md` §11.9）⇒ **今后不得再提议为改名而重建常驻 agent**。

## 7. 临时 agent 准入与结案纪律（**T62-B 新增；本节的目的是「抑制新增」**）
> **立节理由**：委任书 §14.6「agent 数无上限增长 = 另一种臃肿」。物理精简在本工具层做不到（无删除 API），**唯一可施力的方向是入口**（少新建）与**结案**（不留悬案）。
**7.1 准入四问（机械可核对；任一答「否」⇒ 不新建，改为在既有 agent 上续做或由主管自己执行）**
1. **能否不做？** —— 该产出是否已存在于落盘文档（先按 **§7.3 语义通道**检索，而非只搜关键词）？已存在 ⇒ 不新建（重复建 = 产出现有结论的第二版）。
2. **能否并入既有常驻？** —— 该任务是否落在需求／开发／测试／结构任一的既有写域内？在 ⇒ 交该常驻（**跨域走主管转发**，不直接派）。
3. **产出路径是否可预先命名？** —— 能否**在派单前**写出确切的落盘路径（`git ls-files` 可见的路径）？写不出 ⇒ **不得派单**。
4. **完成条件是否可机械判定？** —— 能否写成一条命令／一个断言数／一个文件的存在性？写不出 ⇒ 不得派单（否则必然产生「未落盘」悬案）。
**7.2 登记四项必填（派单当轮即写入本册 §3，缺项 = 登记无效）**：**id**（派单后主管快照里的 UUID，**不得先占位后补**）· **一句话目标**（≤30 字，**不含过程动词**：写「产出 X」，不写「研究一下 Y」）· **预期产出落盘路径**（**完整仓库路径**，且必须**不是** `_tmp*` 目录 —— 依 `_tmp` 判据，`_tmp` 下任何文件一律按可清理处理、不得作为证据来源）· **判定完成的条件**（可机械核对：断言数 / 门禁数字 / 文件存在性 / 可指认的 `文件:行`）。
**7.3 结案三判据（全满足才可标「可回收」；委任书 §14.3 四判据的机械化版本）**：① **`ready` 且非 `running`**（`running` 者**绝不标记**）；② **产出可指认到 `git ls-files` 能列出的路径**（或 `.board/` 文档的 `文件:行`/`§节`）—— **硬门槛**：指不出路径 = **未落盘 ⇒ 优先报警，绝不标可回收**；③ **主管不再派单**（depth≥2 者另加：其父已回收且结果已上浮）。
**7.4 两条禁令（均来自本项目已发生的真实误判）**
- ⛔ **「关键词检索 0 命中」不得作为「未落盘」的结论** —— 它只能支持「**没有以该名称落盘**」。**必须补一条语义通道**：读候选父产物的目录／小节标题，用**语义等价的词**再查一遍（实证：`EVIDENCE.md` §41.5 的标题是「**逐条候选审定表**」，而检索词是 `batch|etym|subagent` ⇒ 词汇不重叠，关键词永远抓不到）。
