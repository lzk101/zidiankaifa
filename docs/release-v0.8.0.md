# v0.8.0 — 修复：词首单字符间隙的假词根误拆（词族卡污染）

**发布日期**：2026-09-16

## 问题

查询俄语 `плескание`（溅水），「词族」卡显示的是 **`лес-`（森林）** 的 40 个词
（`леса` / `лесс` / `лёсс` / `леска` / `лесок` …）——**毫不相关的词族**。

同类污染（全部经逐词复核确认）：

| 查询的词 | 释义 | 被误配的词族 | 污染词数 |
| --- | --- | --- | --- |
| `плескание` | 溅水 | `лес-` 森林 | 40 |
| `хлестаться` | 抽打自己 | `лес-` 森林 | 40 |
| `анестезия` | 麻醉 | `нес-` 携带 | 40 |
| `ателье` | 画室/工作室 | `тел-` 身体 | 40 |

规模：全库 101,512 条俄语词条中，**342 词**呈此形态，其中 **267 词**被误拆。

## 根因

`packages/core/src/db/index.ts` 的 `breakdownWord()` 用两道守卫拦截「词首有一段解释不了的间隙」的误拆：

```ts
// 守卫一：词头 1 字符间隙 + 单片段 → 判为不可拆
if (parts.length === 1 && parts[0].start === 1) return [];

// 守卫二：词首间隙 ≥2 且 gap 无法被前缀解释 → 判为误拆
if (parts.length && parts[0].start >= 2) { /* gapExplain */ }
```

**两道守卫恰好都放过 `gap === 1` 的情形**：

- 守卫一要求 `parts.length === 1`，而 `плескание` 拆出 `лес-@1 + -ка@4 + -ние@6` 共 **3 个片段** → 不触发；
- 守卫二要求 `parts[0].start >= 2`，而它 `start === 1` → 不触发。

于是「词首单字符被跳过 + 词中撞上一个日常基础词根」的组合全部漏网。
假词根库偏偏只收日常基础词（`лес` 森林、`тел` 身体、`нес` 携带、`лет` 飞、`вер` 信），**最容易被撞上**。

**★ 覆盖率阈值对此完全无效**：`зверство` 覆盖率 8/8 = **1.00**、`плескание` 8/9 = **0.89**，
远高于阈值 `BREAKDOWN_MIN_COVERAGE = 0.55`。这是「阈值型防护」的固有盲区——只能靠**位置判据**修。

## 修复

一行改动（`packages/core/src/db/index.ts`）：守卫二的阈值 `>= 2` → **`>= 1`**。

```diff
- if (parts.length && parts[0].start >= 2) {
+ if (parts.length && parts[0].start >= 1) {
```

语义上它**不是新规则**，而是**补齐原规则的覆盖漏洞**：让 `gap = 1` 与 `gap ≥ 2` 适用同一条判据
——「词首间隙必须能被库内某个前缀**精确解释**（`x.stem === gap`），否则判为误拆」。

### 为什么不选「无条件禁止 gap = 1」

对照组实测：无条件禁止会**额外误杀 `удачный`**（真实拆解 `у- + да- + -ный`，「走运的」，
词源 `удача` = `у- + дача`），覆盖率再降 1 词并多 1 例误伤。
`в-` / `о-` / `с-` / `у-` **确实是俄语真前缀**（库内有 4 个单字符前缀词素），必须放行。

## ⚠ 已知残余（如实披露）

本次修复的范围定义是「**词首 gap=1 且该 gap 字符不属于库内前缀集**」，此范围内 **267/267 全消除**。
但修复后仍有 **75 词**呈「gap=1 且 gap 字符**是** `в`/`о`/`с`/`у`」形态，其首片段分布为
**`да-`×63 / `уч-`×11 / `дн-`×1**：

- `да-` × 63（如 `удаваться` = `у + да- + -вать`）—— `да-` 源自 `дать`（给），对 `удаваться` 属**边缘可辩护**（`удача` 确含 `да-` 词源），但会与 `дача` / `дательный` 词族混同；
- **`уч-` × 11（`сучить` / `сучок` / `сучковатый` …）与 `дн-` × 1（`однако`）是真假词根污染**。

**根因**：本次修法只做**字母级**判定（gap 字符 ∈ 前缀字母表），不做**词素级**判定
（该字母是否真被匹配为前缀）。消除它们需新增「词素级 + 词源一致性」判据，属**新机制**而非本 bug 修复。

**⇒ 已列为 v0.9.0 的 P0 项，并在 `ru_morph_defects.mjs` 中留红断言**（红即待办，不删除断言）。
本迭代不扩大范围：这 75 词**修复前就已可拆**（`gapExplain` 对 `gap ≥ 2` 早已放行同类），**修复未新增它们**，非回归。

## 覆盖率目标说明

本次迭代**不设覆盖率提升目标**。原 A2 目标「俄语拆解覆盖率 30.8% → >45%」经评估需要
**补充约 67～99 条经词源审定的词根**（只改规则的零新增上限为 **36.54%**，不足以达标），
且放宽阈值会造出 `вдыхать = {в- + -ать}` 这类空心骨架（质量塌陷，L4 空洞≥3 从 134 冲到 162–204）。
⇒ **补词素与覆盖率提升移入 v0.9.0**，本迭代优先保证**正确性**（符合项目原则「正确性 > 覆盖率」：
误拆污染用户可见词族是离散正确性缺陷，覆盖率不足只是功能稀疏）。

## ⚠️ 本次 Release 不含安装包（仅源码）

`apps/web/dist` **未重建**，仍为 v0.7.1 产物，故 **UI 关于页会显示「我的电子辞典 v0.7.1」而实际版本为 0.8.0**。

原因：构建环境（受限沙箱）**禁止带管道 stdio 的 spawn**（`spawn EPERM`），而 `vite build` 在三个环节都依赖 esbuild
—— 配置打包、`commonjs--resolver` 的 realpath 探测、`vite:build-html`；esbuild 必须用管道与后端进程 IPC。
已用判别实验逐一排除绕行方案（`stdio:'inherit'` 可行但 esbuild 协议需要管道；无 wasm 变体；vite 用命名导入取 `exec`，ESM 活绑定只读，无法 monkey-patch）。
⇒ **无合法绕行路径**。处置与命令已写入 `AGENTS.md` 第 3 节。

**恢复正常发布只需在普通（非受限）终端执行**：

```powershell
$env:ELECTRON_MIRROR='https://npmmirror.com/mirrors/electron/'
$env:electron_config_cache='D:\lzk17\Documents\zidiankaifa\.electron-cache'
$env:ELECTRON_BUILDER_CACHE='D:\lzk17\Documents\zidiankaifa\.eb-cache'
pnpm --filter @zidiankaifa/web build
pnpm --filter @zidiankaifa/desktop build
```

**功能层面本次修复不受影响**：词族拆解逻辑在 `packages/core`（已构建成功），桌面端运行时读的是 `apps/desktop` + core 的 `dist` + 词库，
UI 版本号显示是**唯一**受影响项。若需要，可直接下载上一版安装包覆盖安装 —— 但请注意它内含的是 **v0.7.1 的 core**，**不含本次 D1 修复**。
